# Приёмка и демо: умный подбор подрядчиков

Подготовлено с помощью Codex в рамках роли проверки качества. Базовая проверенная версия: `df173a9` (23.09.2026). Источники требований: `docs/TASK.md`, `docs/CASE_SPEC_RU.md`, `docs/RUBRIC.md`. Этот документ фиксирует проверку прототипа, а не гарантирует готовность будущих версий.

## Воспроизводимые сценарии

Запустить сервер из корня проекта после установки зависимостей:

```powershell
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --port 8000
```

В другом PowerShell выполнить базовый запрос (используется UTF-8):

```powershell
$query = @{
    city = 'Алматы'
    category = 'Ведущий'
    event_type = 'свадьба'
    date = '2026-10-15'
    budget_kzt = 1000000
}
$body = [System.Text.Encoding]::UTF8.GetBytes(($query | ConvertTo-Json))
$result = Invoke-RestMethod -Uri 'http://127.0.0.1:8000/match' -Method Post -ContentType 'application/json; charset=utf-8' -Body $body
$result | ConvertTo-Json -Depth 10
```

Для каждого следующего сценария менять поля `$query`, заново вычислять `$body` и отправлять запрос. Каждый сценарий ниже начинается с базового запроса; изменения не накапливаются.

| Сценарий | Изменение относительно базового | Наблюдалось в df173a9 |
|---|---|---|
| Плотная категория | Нет | `found`, 3 карточки: HK-35215, HK-42352, HK-27222 |
| Редкая категория | category = Флорист | `found`, 2 карточки: HK-90001, HK-39372; объяснено сокращение выдачи |
| Никто не проходит условия | budget_kzt = 0 | `no_match`, 0 карточек, текст причины |
| Вторая дата | date = 2026-10-16 | `found`, 2 карточки: HK-77838, HK-44923 |
| Детерминизм | Повторить базовый запрос трижды | Порядок ID должен оставаться одинаковым |

Дополнительно проверить третий исход `no_category_in_city`: взять сочетание города и категории, отсутствующее в каталоге; сверить с `/options` и CSV. Не выдавать технически несуществующее название категории за реальный пользовательский сценарий.

Приведённые ID — наблюдения для конкретного коммита и официального CSV, не данные для подстановки в приложение. После изменения ранжирования повторно проверить и обновить наблюдения.

## Результат первого прогона

- 40 тестов прошли (`python -m pytest -q -p no:cacheprovider`), 1 предупреждение устаревающего alias в зависимости Starlette/AnyIO. Python 3.12, зависимости из requirements.txt установлены отдельно для ревью.
- Сервер реально запущен через uvicorn; `/health`: status ok, 66 профилей. Главная страница: HTTP 200.
- Выполнены HTTP-запросы плотной/редкой категорий, нулевого бюджета, второй даты и дат вне покрытия. Локальные ответы заняли примерно 3–96 мс; это не нагрузочное тестирование и не измерение LLM.
- CSV репозитория побайтно совпал со скачанным официальным CSV.
- Полное браузерное прохождение формы и чистая установка строго по README пока не выполнены.

## Открытые проблемы версии df173a9

1. **README:** остаются шаблонные поля, нет воспроизводимых шагов демо и описания офлайн-режима. Запуск по README — условие допуска согласно правилам, указанным в docs/HACKATHON_RULES.md. Заполнить до сдачи и проверить на чистом окружении.
2. **Календарь:** официальный диапазон 2026-09-23…2026-12-31. Запросы на 2027-01-01 и 2026-01-01 возвращают карточки с утверждением «по календарю свободен», хотя покрытия нет. Предлагается проверять границы на сервере и в форме; добавить тесты обеих границ и дней за пределами. До исправления не демонстрировать такие ответы как достоверные.
3. **Описание AI:** app/explain.py сейчас склеивает факты в шаблон; LLM — TODO. Документация должна различать реализованный режим и план. Нельзя представлять шаблон как выполненный вызов модели. Сам кейс разрешает LLM, но не обязывает использовать конкретного провайдера.

## Чек-лист перед сдачей

- [ ] Все обязательные поля есть; ошибочные значения дают понятную ошибку.
- [ ] Не более трёх карточек, в каждой имя, категория, город, цена и конкретное объяснение.
- [ ] Занятые подрядчики и площадки исключаются; проверены бюджет, формат, язык и часы.
- [ ] Меньше трёх результатов и все три исхода объясняются словами.
- [ ] Одинаковый запрос сохраняет порядок, две даты дают подтверждённое календарём различие.
- [ ] Объяснения без имён различимы по полезным фактам, а не только по формальной уникальности текста.
- [ ] Диапазон календаря проверен на сервере и в форме.
- [ ] Синтетические и восстановленные поля отмечены; официальные синтетические записи не называются собственными добавлениями команды.
- [ ] Запуск по README проверен без личного API-аккаунта; указаны источники и ограничения.
- [ ] Если добавлен LLM: проверены недоступность API, таймаут, неверный ответ, fallback, отсутствие выдуманных фактов, общее время до 10 секунд.
- [ ] Проверены тесты, запуск, rules-check и видимость часового результата на GitHub.

## Ценность и бизнес-гипотеза

Пользователь — клиент, выбирающий подрядчика на мероприятие. Потенциальный покупатель — агрегатор или ивент-агентство. Польза: короткий список с проверяемыми причинами выбора и отказа вместо ручного просмотра каталога.

Гипотеза монетизации: B2B-подписка или плата за использование модуля подбора. Спрос и готовность платить ещё не проверены. Комиссия с бронирования не подтверждена текущим MVP: бронирований и атрибуции сделок нет.

Метрики пилота: время до короткого списка, предпочтение рекомендаций по сравнению с обычными фильтрами, доля ошибок ограничений и фактов, переходы к контакту. Для себестоимости измерять запросы, расходы API, хостинг и обновление каталога; не заявлять выручку или маржу без данных.

Ограничения: цена «от» не равна окончательной смете; календарю требуется регулярное обновление; анонимизированный и частично синтетический набор подтверждает работу прототипа, но не рыночный спрос.

## Повторная приёмка 24248cd — 23.09.2026

Проверено Codex по поручению Nurdaulet. Старые результаты выше относятся к df173a9; ниже — отдельный прогон актуального снимка 24248cd. Код приложения, README и тесты не изменялись.

### Установка и окружение

Проверялся чистый архив git-коммита без .env и прежних зависимостей, а не сетевой clone: доступ Git из приложения ограничен. Windows, PowerShell. Переменные OPENAI_API_KEY и OPENAI_MODEL очищены только для процесса проверки; системные настройки ключа не менялись.

1. Системная команда `python` здесь означает **Python 3.8.2**, ниже заявленного минимума 3.9. Создание окружения возможно, но установка requirements.txt остановилась на uvicorn==0.34.2. Это несоответствие окружения требованиям, а не доказательство поломки проекта на поддерживаемом Python.
2. `python3` в этом PowerShell отсутствует. README предлагает этот вызов в блоке «Без make (например, на Windows)», далее использует `.venv/bin/python`; Windows-путь дан только комментарием. Для новичка инструкции не копируются буквально. Нужен отдельный блок PowerShell с предварительной проверкой версии Python.
3. С доступным Python **3.12** создано новое окружение `.venv312`, установка requirements.txt успешна. Запуск через `.venv312\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8767` успешен. Порт изменён для изоляции от возможного пользовательского сервера. Таким образом, подтверждён запуск после выбора поддерживаемого Python и адаптации путей, а не буквальная Windows-инструкция README.
4. **93 passed, 1 warning in 0.87 s** (`python -m pytest -q -p no:cacheprovider`). Warning — устаревающий alias BlockingPortal в зависимости Starlette/AnyIO. README пока пишет 77 тестов.

### Статус предыдущих замечаний

- **README — существенно исправлен, но не полностью.** Основные разделы и пять корректных демо-сценариев появились. Остались Windows-команды, устаревшее число тестов и заполнители участников. rules-check: 0 ERROR, 1 WARN — 3 строки с заполнителями. Раздел доступа также обещает AI после указания ключа, хотя код требует и непустой OPENAI_MODEL; это стоит явно написать в том же абзаце.
- **Календарь — ещё не исправлен в 24248cd.** Через браузер дата 2027-01-01 допустима и возвращает 3 карточки. Через API 2026-09-22 и 2027-01-01 также дают HTTP 200 и 3 карточки. В matched_facts всё ещё записывается доступность вне покрытия. Обе допустимые границы 2026-09-23 и 2026-12-31 дают HTTP 200. Разработчик сообщил, что готовит исправление; этот прогон его не включает.
- **LLM — реализация появилась.** Есть отдельный модуль вызова, проверка структуры, лексический валидатор и fallback. Без ключа реально работает весь демо-сценарий. 93 офлайн-теста прошли. Живой OpenAI-вызов, скорость 2–2.6 с и общая гарантия ответа <10 с в AI-режиме независимо не проверялись; это пока сообщение разработчика. Лексическая проверка не доказывает отсутствие любых смысловых галлюцинаций.
